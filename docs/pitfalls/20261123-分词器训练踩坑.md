# 分词器训练踩坑（20261123）

## 1. 逐个 token 解码必定是乱码

**症状**：`tok.decode([token_id])` 输出 `�`，切分对照表完全读不了。

**原因**：一个汉字在 UTF-8 下是 3 字节，BPE 可能把它拆成 2 段甚至 3 段。单个片段不是合法 UTF-8 序列，解码只能给替换符。

**解法**：累积解码取增量——每次多解一个 token，和上一次的结果做差，差值就是这个 token 贡献的文字。末尾不完整的字节用 `rstrip("\ufffd")` 剥掉。

```python
units, prev = [], ""
for i in range(1, len(ids) + 1):
    cur = tok.decode(ids[:i]).rstrip("\ufffd")   # 剥掉尾部不完整字节
    added = cur[len(prev):]
    prev = cur
    # added 为空 => 这个 token 是半个字，把它累加到下一个完整字上
```

配套还要做一件事：把 `added` 为空的 token 归并到后面那个字，并累计 `×n`，否则切片表里全是空格子。

## 2. `<unk>` 不可逆，而且不报错

**症状**：`decode(encode(s)) != s`，但没有任何异常，只是少了几个字。

**原因**：词表外字符被映射到 `<unk>`，多个不同的字共享同一个 `<unk>` id，解码时无法还原。Fuse decoder 会把 `<unk>` 直接吞掉——所以文本是**静默丢失**，比报错更危险。

**教训**：训练完必须跑一遍 round-trip 校验（`decode(encode(s)) == s`），不能只看 token 数。

```python
assert all(tok.decode(tok.encode(s).ids) == s for s in probe_sentences)
```

跨领域使用时这条必然失败，这是词表与语料不匹配的信号，不是 bug。

## 3. pip 装不进系统 site-packages（本机环境）

**症状**：`pip install tokenizers` 跑到一半 `SIGTERM` 中断，无任何错误信息，`python -c "import tokenizers"` 仍然 `ModuleNotFoundError`。

**原因**：本机沙箱不允许写入系统 Python 的 `site-packages`，管道被静默杀掉。

**解法**：装到项目本地再挂载路径。

```bash
pip install --target ./pydeps tokenizers tiktoken
```

```python
import sys
from pathlib import Path
sys.path.insert(0, str(Path(__file__).parent / "pydeps"))
```

**注意**：这是本机环境特有的绕行方案，**不要提交到仓库**（`pydeps/` 已在 `.gitignore` 里）。正常环境直接 `pip install -r requirements.txt` 即可。
