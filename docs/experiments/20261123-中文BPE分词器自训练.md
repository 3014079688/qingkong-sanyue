# 20261123 · 中文 BPE 分词器自训练

## 1. 一句话结论

在自己的诗词语料上，自训 BPE 把压缩率做到 **0.71 token/字**，比 o200k_base 的 1.23 好 42%；但换到现代中文场景立刻失效——105 个字里 30 个不在词表，解码直接丢字。**词表的领域专精是以泛化能力为代价换来的。**

## 2. 目标与假设

- **要解决什么问题**：把「token 是怎么被生产出来的」这件事从概念变成可观测的实验。不追求训出一个能用的分词器，追求把词表、压缩率、覆盖率三者的关系量化出来。
- **本次假设**：① 自训分词器在训练语料同域文本上压缩率应优于商用分词器；② 词表外的字符会导致不可逆的信息丢失，且字节兜底能解决但代价更高。
- **验证指标**：主指标 `token/字`（留出集）；辅助指标 OOV 率、编解码无损性。

## 3. 配置

- 代码 commit / 分支：`exp/20261123-token-bpe`
- 配置文件路径：`configs/tokenizer/bpe-20261123.json`
- 关键超参：`vocab_size=9911`、`min_frequency=1`、`train_ratio=0.95`；BPE 训练本身无 lr/epoch 概念
- 随机种子：`20261123`（用于打乱语料后切分训练/留出集）
- 运行环境：Windows，Python 3.13.14，`tokenizers==0.23.3`，`tiktoken==0.14.0`；**纯 CPU，未使用 GPU**（RTX 3050 Ti 4GB 全程空闲，分词器训练不需要显卡）

两种方案：

| 方案 | 初始词表 | 说明 |
| --- | --- | --- |
| char_start | 语料中全部 3,312 个汉字 | 词表小、可读性强；未见过的字变 `<unk>` |
| byte_start | 256 个 UTF-8 字节（GPT-2 做法） | 永不产生未知字符；生僻字需多个 token 拼 |

## 4. 数据

- **数据集来源与版本**：全唐诗第 0 卷，来自 `chinese-poetry/chinese-poetry` 仓库
  `全唐诗/poet.tang.0.json`
- **获取方式**：原始数据不入库（`.gitignore` 已排除 `data/raw/*`），需自行下载到 `data/raw/tang0.json`
- **校验值**：`sha256 = 4f88f429938082523cdc72a1612bd7a7c3e3f7a33f8192c61ae51340efc3c92d`，`408,405` 字节。脚本启动时会强制校验，不符直接退出
- **样本量**：去重后 5,041 条 / 58,744 字符 / 3,353 个不同字符；训练 4,788 条，留出 253 条（2,925 字符）
- **预处理**：每首诗拆成「标题 + 各行」，逐行 strip 后整行去重；无其他清洗（保留标点，因为标点在真实文本里也占 token）


## 6. 结论与下一步

- **结论是否符合假设**：
  - 假设①成立，而且比预期更强。域内 0.71 vs o200k 1.23——自训分词器赢了 42%。原因是 o200k 的词表按现代中文和英文的频次构建，繁体汉字与文言虚词在它那里都是长尾，一个字常常要 2 个 token 以上。
  - 假设②成立。`<unk>` 造成不可逆丢字，字节兜底确实解决了，但代价是 0.84（域内）和 1.25（域外）。
- **意外发现**：
  1. **同一条结论会随语料翻转。** 早先一次混合语料（唐诗 + 现代技术文档）的实验里，自训分词器是 0.98、o200k 是 0.57，商用完胜；这次纯诗词语料，结论完全反过来。压缩率根本不是分词器的固有属性，而是**分词器与语料匹配度的函数**。任何「某分词器更好」的说法都必须带上语料条件。
  2. **字节起始方案在域内并没有想象中差。** 0.84 已经优于两个商用分词器，说明只要语料足够，字节级起步也能把常用字完整合出来。
  3. **BPE 学到的合并规则就是语料的指纹。** 本次前 12 条是：`樂章 / 德，/ 吹曲 / ，萬 / 武后 / 風。/ 春。/ 聲。/ ，神 / 人。/ 太子 / 樂舞`。全是唐诗高频词，没有一条现代词汇。
- **下一步动作**：
  1. 把语料换成现代中文（技术文档、课程笔记），重跑同样配置，验证「结论随语料翻转」这一判断是否稳定。
  2. 词表规模扫描：9911 → 20000 → 50000，画「词表大小 vs 域内压缩率 vs 域外 OOV」三条曲线，找拐点。
  3. 引入 BPE-dropout 做子词正则，缓解 OOV 问题（比字节兜底更优雅）。
- **是否值得继续投入**：**N（作为研究课题）**。结论已经清楚，边际收益递减。但**代码可复用**：`train_bpe.py` 换个语料就能给出任意领域的分词器，这个工具价值保留。
