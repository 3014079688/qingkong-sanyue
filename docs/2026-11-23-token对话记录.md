## 一、token 是什么

token 是**模型读写文字时用的最小计数单位**。它不是字也不是词，是分词器（tokenizer）切出来的片段。

一句话进去，先被切块，每块查表换成一个编号，模型内部只看见编号列表：

```
我喜欢自然语言处理
  ↓ 切分
我 | 喜欢 | 自然 | 语言 | 处理
  ↓ 查表
[1024, 3721, 8890, 4412, 6203]
```

几个关键点：

- **切法不按字数固定。** 常见词、汉字往往独立成 token；生僻词、长英文单词会被拆开（`unbelievable` → `un` + `believ` + `able`）。
- **词表是有限的。** 主流模型词表约 10 万~20 万条，拿有限碎片拼无限文本，比给每个词编号更省空间，也更能容错。

为什么值得关心：上下文长度、响应速度、计费**全都按 token 算**。

- 「128K 上下文」= 一次能塞进对话的总 token 上限，包含系统提示、历史对话、当前提问，以及留给回答的空间。装满了就得截断旧内容。
- 计费双向算：输入（读）和输出（生成）分别计价，输出通常贵 2~4 倍。
- 生成是一个 token 一个 token 往外蹦，所以回答越长越慢——那个「打字机效果」不是装饰。

粗略换算（不同分词器有差异，仅量级参考）：

| 内容 | 大约 token 数 |
|---|---|
| 1 个汉字 | ≈ 1 个（现代中文优化的模型），旧模型 1.5~2 个 |
| 1 个英文单词 | ≈ 1.3 个 |
| 1000 个汉字 | ≈ 1000~1500 个 |
| 一页 A4 中文文档 | ≈ 800~1200 个 |

**注意区分**：`token` 在不同语境里是三件不相干的事。登录/接口里的 token 是身份令牌；区块链里的 token 是代币；只有大模型语境里它才是文本计数单位。

## 二、有没有自己生产 token 的方法

「生产」有四种自主程度，从租到造：

| 档位 | 做法 | 本质 | 本机可行性 |
|---|---|---|---|
| ① | 调云端 API | 租 token，按量付费 | 随时可用 |
| ② | 本地跑开源模型 | token 由自己的显卡算 | 4GB 显存 → 只能跑 4B 以下量化模型 |
| ③ | 自己训练分词器 | 自己定义 token 的切法 | **完全可行，CPU 就够** |
| ④ | 从零训练模型 | 连权重和词表都自建 | 4GB 显存只能训千万参数级玩具 |

### 各档的具体判断

**② 本地跑开源模型**——零 token 费用的现实解法，但有硬限制：
- 4B 级模型（qwen3:4b、gemma3:4b）量化到 Q4 约 2.5GB，能完整进显存，约 30~60 token/s，体验可接受。
- 7B 模型 Q4 约 4.4GB，**超过 4GB 显存**，会溢到内存，掉到个位数 token/s，基本没法用。
- 代价是能力上限：4B 与云端大模型差一个量级。

**③ 自己训练分词器**——字面意义的「自己生产 token」，门槛最低。用 HuggingFace `tokenizers` 跑 BPE，喂自己的语料，几十秒出词表。
- 有个天花板：**词表必须和权重配套**。换了分词器，原模型权重就作废，因为编号对不上。

**④ 从零训练模型**——走 nanoGPT / llm.c，4GB 显存能训到千万参数级字符模型，成果是「能拼出像英文的字母串」。学习价值大于实用价值。

**不推荐**：自建代理池、拼车共享 API key、反代免费额度——多数违反服务条款，账号随时封。

## 三、动手：亲手训练一个中文 BPE 分词器

选的是第 ③ 档。目标不是拿到一个能用的分词器，而是**看清 token 是怎么被造出来的**。

### 3.1 语料

联网找语料接连碰壁，过程记录：

| 来源 | 结果 |
|---|---|
| projectgutenberg.org | 站点维护中，返回 HTML 维护页 |
| zh.wikisource.org | 不可达（超时） |
| cdn.jsdelivr.net（chinese-poetry 仓库） | 403，仓库超过 50MB 上限 |
| **raw.githubusercontent.com** | **200，可用** |

最终语料：

- 全唐诗 1 卷（`chinese-poetry/chinese-poetry`，5,313 条）
- 本机中文技术文档 7 篇（`~/.workbuddy/skills/**/*.md`）
- 去重后 **5,048 条 / 113,452 字符 / 3,911 个不同字符**
- 划分：训练 4,795 条，留出 253 条（压缩率只在留出集上计算，避免自评自夸）

### 3.2 两种训练方案

| 方案 | 初始词表 | 特点 |
|---|---|---|
| A 字符表起步 | 语料里所有汉字（3,302 个） | 词表小、可读性强，**没见过的新字变 `<unk>`** |
| B 字节起步 | 256 个 UTF-8 字节（GPT-2 做法） | **永不出现未知字符**，代价是生僻字多花 token |

词表规模都设 9,911 条（3,302 字符 + 6,609 条合并规则）。

### 3.3 结果

留出集共 57,747 个字符：

| 分词器 | 词表 | 留出集 token | token/字 | 生僻字丢失 | 无损还原 |
|---|---|---|---|---|---|
| 字符级基线 | 3,911 | 57,747 | 1.00 | 0% | 通过 |
| 我训的 · 字符表起步 | 9,911 | 56,873 | 0.98 | **29%** | **失败** |
| 我训的 · 字节起步 | 9,911 | 67,874 | 1.18 | 0% | 通过 |
| cl100k_base | 约 20 万 | 40,962 | 0.71 | 0% | 通过 |
| o200k_base | 约 20 万 | 33,171 | **0.57** | 0% | 通过 |

生僻字覆盖率用 5 句含生僻字的现代中文测（105 字）。

### 3.4 四个发现

**1. 语料决定词表。** BPE 从这份语料学出的合并规则：

```
樂章 / 吹曲 / 郊廟 / 太子 / 昊天 / 武后 / 德， / 風。 / 聲。
```

全是唐诗高频词，一个技术词都没有。换菜谱语料，词表里就是「少许」「爆香」；换代码语料，就是「函数」「返回值」。**词表是语料的指纹。**

**2. 11 万字练不出好词表。** 0.98 vs o200k 的 0.57——同一句话，商用分词器只花 58% 的 token。差距来自语料规模：11 万字 vs TB 级多语种文本。

**3. 词表小了，字会丢。** 最需要警惕的发现：

```
原文：智能机器人专业的同学在做步态加速度特征采集。
还原：智能器人的同在步加速度特征采集。
```

「机」「专」「业」直接消失了。字符表起步方案遇到词表外汉字只能吐 `<unk>`，而它是不可逆的。这就是「词表必须和权重配套」的真实后果——编号对不上，信息就丢。

**4. 字节兜底能兜住生僻字，但更贵。** 初始词表设成 256 个字节后，任何字都能拼出来，永不丢字，代价是 1.18 token/字，**比字符级还差**。压缩率与覆盖率之间是取舍，商用词表靠「更大的词表 + 海量语料」两头兼顾。

### 3.5 切分对照（第一句，24 字）

| 分词器 | 切分结果 | token 数 |
|---|---|---|
| o200k_base | `智能 \| 机器人 \| 专业 \| 的 \| 同 \| 学 \| 在 \| 做 \| 步 \| 态 \| 加 \| 速度 \| 特 \| 征 \| 采 \| 集 \| 。` | 17 |
| cl100k_base | 同样内容，但「智」「在」「特」「征」各花 2 个 token | 26 |
| 我训的 · 字符表起步 | `智 \| 能×2 \| 器 \| 人×3 \| 的 \| 同×2 \| 在×2 \| 步×2 \| 加 \| 速 \| 度 \| 特 \| 征 \| 采 \| 集。`（丢了「机专业」，还有几个字被拆碎） | 21 |
| 我训的 · 字节起步 | 每个常用汉字基本 2 个 token 起（一个 UTF-8 汉字 3 字节，没能合并成一个整字） | 30 |

`×2` 表示这一个字花掉了 2 个 token。

## 四、踩过的坑

技术细节，复现时会再遇到。

**1. pip 装不进系统 site-packages。** 沙箱禁止写入，`pip install` 会 SIGTERM 中断且无输出。解法：装到项目本地，脚本内挂载路径。

```python
pip install --target ./pydeps tokenizers tiktoken
```

```python
import sys
from pathlib import Path
sys.path.insert(0, str(Path(__file__).parent / "pydeps"))
```

**2. 逐个 token 解码是乱码。** 一个汉字可能被拆成 2~3 个字节片段，单独解码必然出现 `�`。解法：累积解码取增量，并把不完整的字节片段归到它最终拼成的那个字上。

```python
units, prev = [], ""
for i in range(1, len(ids) + 1):
    cur = tok.decode(ids[:i]).rstrip("\ufffd")   # 剥掉尾部不完整字节
    added = cur[len(prev):]
    prev = cur
```

**3. `<unk>` 不可逆。** 这不是 bug，是词表外字符的固有代价。用它做了第 3 个发现的证据。
